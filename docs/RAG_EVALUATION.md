# RAG Evaluation

This evaluation measures the local grounded-answer layer over CFPB public complaint narratives. It does not use model memory and it does not require a live LLM key.

## What Was Evaluated

- Retrieval over 5,343 indexed CFPB public complaint narratives.
- Hybrid search using TF-IDF lexical retrieval, local LSA/SVD dense vectors, metadata filters, and rank fusion.
- Metadata filtering for product, company, issue, state, and date windows.
- Citation validity using CFPB complaint IDs.
- Deterministic no-key answer fallback, which assembles answers only from retrieved complaint citations and analytics outputs.
- Abstention behavior when filters return no matching evidence.

## Evaluation Set

The evaluation file is `evaluation/rag_questions.json`.

It contains 45 analyst-style questions covering:

- product-specific complaint themes;
- company-specific complaint themes;
- issue-specific retrieval;
- state and date filters;
- comparison prompts;
- impossible filters where the right behavior is abstention.

## Known Miss

One intentionally awkward prompt, "moon mortgages", still retrieves ordinary mortgage-related evidence because the local retriever sees the mortgage term. That is a real limitation of the current no-key retrieval layer. In an enterprise version, this should be handled with stronger query understanding, stricter unsupported-term detection, and human review for low-confidence answers.

## How To Reproduce

```bash
python scripts/build_rag_index.py
python scripts/evaluate_rag.py
```

## Interpretation

The RAG layer is suitable for evidence-backed complaint exploration, not autonomous decision-making. It should help an analyst find relevant complaint text, see deterministic context, and draft a cited answer. It should not infer misconduct, calculate business metrics with an LLM, or answer without evidence.
